# Delegated Roles

The saved project mode is triumvirate. For change tasks, AGENTS.md authorizes the primary to use the installed team procedure within the human-approved task scope. Installation alone does not grant scope approval. Only the primary coordinates; delegates receive effectiveTeamMode and their explicit phase and never spawn another team.

The installed roles are:

- change-implementer: implement the approved reviewed plan within assigned files, preserve other edits, self-check and fix confirmed findings; never commit, expand scope or delegate further.
- change-auditor: one fresh invocation for plan-review, one for implementation-review, and a separate fresh invocation for verification. Reviews read only and execute no project code. Verification runs only authorized checks against the supplied matching candidate and suitable isolated environment, and never fixes product files.

Give each delegate task/plan/candidate identity, original criteria, actual baseline and dirty edits, effective mode, phase, cwd, permitted commands/resources, ownership, scratch/report paths and expected result. Do not assume inherited history supplies these. Check supported history exclusion and disclose limits to freshness.

The primary owns acceptance and task/evidence records; product edits belong to the assigned implementer. Assign preparation of verification infrastructure separately to the implementer. Preserve staged, unstaged and relevant untracked edits; do not overlap ownership, reset, stage or adopt unrelated changes.

Native role discovery, lifecycle tools, actual model/effort and inherited permissions require runtime evidence. Both roles are customized to pin gpt-6.1-sol/high. Codex delegates inherit parent sandbox/approval policy; role instructions are organizational boundaries, not separate filesystem or network isolation. No model substitution, permission weakening or silent single-agent fallback is allowed.

A copy/worktree is not isolation. The coordinator supplies enforced read-only product inputs, bounded scratch/temp writes, necessary dependencies and authorized commands; the verifier confirms correspondence and actual probes before execution. Missing prerequisites leave the phase blocked. Do not install dependencies or access services to make a phase pass without approval.

Freeze product writes during review/verification. New material inputs invalidate affected evidence. The implementer fixes findings; the auditor confirms fixes; the coordinator resolves disputes with evidence. On interruption, retain a checkpoint and recheck files, identity, authorization, active delegates and stale evidence before resuming.

Completion differs from explicit closure. Use close only if the native runtime supports it, and report its absence. Timeout, quota failure, a completed child or exit code zero does not establish task acceptance or native root completion.
