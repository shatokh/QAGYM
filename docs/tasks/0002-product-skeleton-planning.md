## Scope

This planning task defines the recommended first implementation task sequence for the product skeleton.

The recommended split is:

1. `0003` - Repository Infrastructure Skeleton.
2. `0004` - Frontend App Skeleton.
3. `0005` - Backend App Skeleton.
4. `0006` - Git Repository Baseline.
5. `0007` - Local Database and Prisma Skeleton.
6. `0008` - Local Runtime Wiring.
7. `0009` - Initial CI Quality Gates.

This task may update documentation to capture that split after review.

`0006` was inserted after the backend skeleton by explicit human approval. The
remaining proposed task numbers were shifted to keep task IDs unique.

## Recommended Implementation Task Split

### 0003 - Repository Infrastructure Skeleton

Behavior type: Infrastructure.

Goal: Create the minimum monorepo/package foundation.

Proposed scope:

- Create `package.json`.
- Create `pnpm-workspace.yaml`.
- Create root TypeScript/tooling config only if needed for the first skeleton.
- Create future folder roots such as `apps/`, `packages/`, and `tests/` only when useful.
- Add basic repository metadata scripts as placeholders only if commands are actually wired.

Out of scope:

- React app implementation.
- NestJS app implementation.
- Prisma schema.
- Docker Compose.
- Business logic.
- Planned bugs.

Recommendation: keep this task small and avoid adding dependencies beyond the minimum needed to establish pnpm workspaces.

### 0004 - Frontend App Skeleton

Behavior type: Infrastructure.

Goal: Create a minimal React + Vite + TypeScript app under `apps/web`.

Proposed scope:

- Create Vite React TypeScript skeleton.
- Add minimal app shell proving the frontend runs.
- Keep frontend libraries beyond React + Vite proposed unless explicitly approved in this task.
- Add no business flows beyond a placeholder clean shell.

Out of scope:

- Catalog implementation.
- Auth implementation.
- Cart or checkout.
- UI kit decision unless approved.
- Planned bugs.

Recommendation: defer React Router, TanStack Query, React Hook Form, frontend Zod usage, and i18n library installation until the first feature task that needs them, unless the user approves them during frontend setup.

### 0005 - Backend App Skeleton

Behavior type: Infrastructure.

Goal: Create a minimal NestJS + TypeScript app under `apps/api`.

Proposed scope:

- Create NestJS skeleton.
- Add a basic health endpoint.
- Establish Zod as the preferred DTO validation direction, but do not build domain DTOs yet.
- Add minimal backend test wiring only if generated by the selected setup or explicitly approved.

Out of scope:

- Auth.
- Catalog.
- Database integration.
- Swagger public/internal contract implementation.
- Planned bugs.

Recommendation: keep the first backend task focused on a running API and health check.

### 0006 - Git Repository Baseline

Behavior type: Infrastructure.

Goal: Initialize Git, create the first project baseline commit, and add explicit
human commit checkpoints to the working process.

This task was inserted after the original planning task. Its detailed scope is
defined in `docs/tasks/0006-git-repository-baseline.md`.

### 0007 - Local Database and Prisma Skeleton

Behavior type: Infrastructure.

Goal: Introduce PostgreSQL + Prisma foundation without product domain complexity.

Proposed scope:

- Add Prisma setup.
- Add initial database configuration.
- Add a minimal schema only if needed to verify connection and migrations.
- Define where seed scenarios will live.

Out of scope:

- Full product schema.
- Demo users.
- Catalog data.
- Orders.
- Planned bug seed scenarios.

Recommendation: decide whether an empty Prisma baseline is enough or whether a tiny health/probe model is needed before approving this task.

### 0008 - Local Runtime Wiring

Behavior type: Infrastructure.

Goal: Wire local runtime for the skeleton.

Proposed scope:

- Add Docker Compose for PostgreSQL and approved runtime services.
- Define environment file examples.
- Document local start commands.
- Ensure frontend and backend can run locally with the database available.

Out of scope:

- Production Dockerfiles.
- Public deployment.
- Observability stack.
- Redis, queues, object storage.

Recommendation: keep Docker Compose local-first and avoid production deployment concerns here.

### 0009 - Initial CI Quality Gates

Behavior type: Infrastructure.

Goal: Add the first CI checks once commands exist.

Proposed scope:

- Add GitHub Actions only after package scripts exist.
- Run available lint/typecheck/test commands.
- Keep CI aligned with documented command names.

Out of scope:

- E2E browser matrix.
- k6 CI load runs.
- Deployment pipeline.
- Coverage gates unless explicitly approved.

Recommendation: add CI after skeleton commands are real, not before.

## Recommendation

Do not create one large "product skeleton" implementation task.

Use the split above. It keeps review size manageable and prevents package setup, app scaffolding, database wiring, Docker, and CI from landing in one broad diff.

The first implementation task should be `0003 - Repository Infrastructure Skeleton`.

## Accepted Review Decisions

- `0003` should create workspace files and the empty root folders needed for the workspace layout.
- Frontend setup should not immediately add React Router, TanStack Query, React Hook Form, frontend Zod, or i18n. Add them later when approved feature tasks need them.
- Backend setup should not immediately add Swagger dependencies. Defer Swagger until API contract or docs work needs it.
- Prisma product schema should wait until the first product data model. Database and Prisma wiring can be planned as a separate minimal task.
- CI should wait until real `lint`, `typecheck`, or `test` commands exist.

## Out of Scope

- Creating `package.json`.
- Initializing pnpm.
- Installing dependencies.
- Creating React, Vite, NestJS, Prisma, Docker, or CI files.
- Creating application code.
- Creating database schema.
- Creating seed data.
- Creating API contracts.
- Creating planned bug entries.
