# Triumvirate

Apply this procedure to the primary agent only when project teamMode is triumvirate or the user explicitly invokes it for this task. Merely installing the skill or roles does not authorize delegation. A delegate follows its assigned role/phase and does not start another team. Keep one native runtime for the whole team, including combined Codex+Claude projects.

The primary plans and coordinates; change-implementer alone edits product files; fresh change-auditor invocations review the plan, review implementation, and independently verify. Preparation of verification infrastructure belongs to a separately scoped implementer assignment. The primary may maintain task/evidence records. These are responsibility boundaries, not per-role filesystem isolation; delegates inherit runtime permissions.

1. Establish the task's effectiveTeamMode separately from saved project mode, user authorization, task ID, baseline (including existing dirty changes), acceptance criteria, plan revision, permitted files, commands, rollback limits, and time/iteration budget. Check actual native capabilities and effective permissions with bounded disposable probes. Read [the operating contract](references/operating-contract.md) before delegating.
2. Spawn a fresh plan-review auditor with the original request and requirements, plan, bounded relevant context, and no author conversation. Resolve blocking findings before implementation. Review never grants missing user authorization.
3. Assign the reviewed plan to an implementer with explicit file ownership and reminders that others may be editing. Require implementation and self-check results, then freeze product writes for review. Preserve user changes; do not reset or silently adopt them.
4. Prepare an exact candidate and suitable isolated verification environment. Include required unchanged inputs, tests, manifests/lockfiles/config, selected untracked files, and deletions. Have a fresh implementation-review auditor inspect the actual delta and contracts without executing project code. A separate fresh verification auditor selects checks from criteria, inspects commands, then runs only authorized checks in the supplied environment. Unavailable isolation or prerequisites means blocked verification.
5. Send defects to the implementer and plan defects to the primary. New product, test, dependency, command, or material configuration changes invalidate affected evidence. Re-review/retest the new candidate. The auditor confirms fixes; the primary may reject a finding only with recorded counterevidence. Material scope/criteria changes return to planning and applicable authorization.
6. Reconcile the tested candidate with the target workspace without overwriting changes since baseline; only the implementer transfers product changes. Before closeout, compare the final workspace and reviewed/tested inputs, resolve material findings, and confirm every mandatory criterion. Use [the evidence contract and checker](references/evidence.md) for a ready-for-closeout checkpoint with an explicit local coordinator ID. Do not invent native root IDs/events or wait for your own future completed event before replying. An external observer or later turn can optionally record actual matching root completion separately. Readiness is not proof of native turn completion; a child's event, exit 0, or confident prose alone establishes neither task acceptance nor runtime completion.

Pass effectiveTeamMode, role, phase, task/plan/candidate identities, cwd, permissions, write locations, and expected report to every delegate. Use distinct native thread identities, not role markers, to distinguish invocations. Limit inherited conversation where supported and disclose any unverified freshness; do not claim adversarial isolation. Auditor reports use pass, changes-requested, or blocked, and include actual evidence and limits.

Run phases sequentially within available slots. Stop after two correction cycles without progress and record the next useful experiment. Timeout, quota, cancellation, missing capabilities, or missing mandatory checks leave an incomplete task with a manual checkpoint, never an implicit single-agent fallback. Resume by checking files, identities, active delegates, and existing authorization before the first unconfirmed phase; do not reapply completed edits. Close delegates only through supported runtime tools; report when closure is unavailable. Do not introduce hooks, automatic session capture, a permanent runner, automatic merge, commits, or publication.
